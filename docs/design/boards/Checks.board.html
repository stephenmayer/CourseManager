What changes, and what doesn't

When a warning is off

  • It disappears from student pages, the course dialog, the student list's check pills, its counts and the "Has warnings" filter.
  • Reasons counselors typed stay on the requests. Switch the check back on and those warnings show as kept again.
  • Done works as before: only errors block it, and errors can't be switched off.
  • The setting is for the whole tool, not per counselor. There are no roles in the prototype (M10).
  • Reset demo data switches every check back on.

Not in this screen

  • Editing the rules themselves (which subjects per grade, the AP limit). That is the graduation rules add-on (Q15, #18).
  • Per-grade or per-student switches.
  • A history of who changed a switch. The row stores when it last changed.

Build shape (issue 1.12)

  • A check_setting table; no row means on.
  • GET /api/checks and PUT /api/checks/{rule}; switching an error off is refused.
  • The service hands only switched-on rules to the checks, so the rules stay pure functions.
  • Header gets a third link, Checks.

One choice for you

Can the two errors be switched off too?

Recommended: no. Unknown and duplicate courses are bad SIS data, and Q5 has them block Done so they never reach the schedule. Letting them be switched off would let a student be marked Done with SS303 on the list. If you want all five switchable, the errors would get switches like the warnings and the Done gate would follow whatever is on.
